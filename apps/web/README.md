# Spanish client

Run `npm ci`, then `npm run dev`. The development server proxies `/api` to localhost:8100; override `API_PROXY_URL` for another local API. Run `npm run build` and `npm test` before integration. In production serve `dist` and proxy `/api` on the same trusted origin. No credentials are persisted in browser storage.

## Local voice activation

The explicit **Activar voz** button requests microphone access and opens an AudioContext. No microphone is requested on page load. Serve the reviewed Spanish Vosk model as `public/models/vosk-model-small-es-0.42.tar.gz` before building. The archive must match vosk-browser's documented directory format. It is not the upstream ZIP renamed to TAR. Model weights are not committed.

Say **Hola asistente**, pause, then ask the question. Idle audio is processed locally by a WASM worker. Only the following question is collected as mono PCM WAV and uploaded to the configured local API. It ends after 1.4 seconds of silence following speech, or 20 seconds maximum; **Terminar pregunta** ends it manually. **Hablar ahora** is an accessible fallback, not a replacement for wake activation. **Desactivar micrófono** releases microphone tracks and the local model. HTTPS or localhost and a foreground active tab are required. There is no promise of background or suspended-tab wake operation.

The simple RMS end-of-question detector is not a production AEC/VAD or barge-in implementation. Wake detection is paused while waiting or speaking to avoid feedback loops. Stop playback with **Detener**. The server must verify evidence before producing audio; the client calls speech only after `verified: true` and never converts model text directly to speech. Browser Web Speech / external speech services are not used.

No real microphone or downloaded model inference was verified by unit tests. The model download, desktop audio behavior, Spanish accents/noisy rooms, wake false positives, and latency require explicit hardware acceptance tests. The old vosk-browser community wrapper must be audited before deployment; it is pinned, not assumed maintained.

## Local acknowledgement

After a locally accepted question is submitted, the voice-enabled UI plays the fixed same-origin `/models/consulting.wav` acknowledgement. This asset must be generated by the model preparation workflow. If missing or autoplay is blocked, the UI explicitly falls back to the visible “Déjame consultar…” status; it does not pretend audio was delivered. This acknowledgement is not an assertion that data was fetched. Clarification responses require `clarification: true`, are displayed as clarification and never spoken or labeled as verified results.

## Validation performed

Production TypeScript/Vite build and unit/DOM tests run successfully in the implementation environment. DOM tests mock the API and do not establish live backend or microphone correctness. The attempted Chromium visual smoke could not start due to the environment's socket restriction; its escalated runner failed before execution. Visual browser QA and real voice acceptance remain pending. The large optional Vosk WASM chunk is lazy-loaded only after enabling voice, not on initial text-client load.

## Dependency security note

Vite was updated to 8.3.5 and Vitest to 4.1.12 after an actual npm audit identified advisories in the initial versions. The optional pinned vosk-browser 0.0.8 wrapper still brings uuid<11.1.1 (GHSA-w5hq-g745-h8pq), for which npm reports no vendor fix. Do not treat a transitive override as a fix for already bundled upstream code. A reviewed wrapper rebuild or maintained alternative is required before a security-sensitive rollout. Keep development servers on loopback and never expose them as production servers. Dependency audit results are time-sensitive and are not a full security review.
